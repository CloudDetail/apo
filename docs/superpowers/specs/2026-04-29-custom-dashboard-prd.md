# 自定义大盘功能优化需求说明书

> 说明：本文为 2026-04-29 的初版需求基线。当前实现和后续验收中，若本文与现有代码、OpenSpec 决策存在差异，应优先参考补充说明 `docs/superpowers/specs/2026-05-06-custom-dashboard-requirement-clarifications.md`。

## 1. 背景

APO 当前包含若干 Grafana 大盘，通过 iframe 嵌入到前端页面中展示。该方式能快速复用 Grafana 能力，但在产品体验和客户交付上存在明显限制：

- 大盘展示界面与 APO 产品体验割裂，难以体现平台自身能力。
- iframe 嵌入方式受 Grafana 页面结构、权限、主题和交互影响，定制空间有限。
- 现有大盘相对固定，用户无法基于自身场景灵活创建大盘。
- 公司技术人员需要类似 Grafana 的查询和图表配置能力，但希望沉淀到 APO 平台内。
- 面向国企客户交付时，需要更完整、统一、专业的原生工作台体验。

因此，本需求将自定义大盘从“Grafana 嵌入展示”调整为“APO 原生自定义可观测性工作台大盘”。

## 2. 产品定位

APO 自定义大盘是一套平台内原生的大盘构建、编辑和展示能力，面向公司技术人员，同时兼顾客户高级用户。用户可以通过模板快速创建大盘，也可以使用自定义 PromQL / VictoriaMetrics 查询语句配置图表组件，在 APO 内完成大盘查看、编辑、布局和权限管理。

本功能不再使用 Grafana 作为 iframe 展示界面。Grafana 可作为能力参考，但自定义大盘的展示、交互和视觉体验由 APO 原生实现。

## 3. 产品目标

### 3.1 核心目标

- 支持用户在 APO 内创建、编辑、查看和管理自定义可观测性大盘。
- 支持模板创建和空白创建，满足快速搭建和自由配置两类场景。
- 支持网格式布局编辑，用户可拖拽调整组件位置和大小。
- 支持预置查询和自定义查询两种查询配置方式。
- MVP 阶段聚焦指标数据，支持 PromQL / VictoriaMetrics 查询。
- 展示界面由 APO 原生实现，形成统一、专业、成熟的运维工作台体验。

### 3.2 体验目标

- 对公司技术人员：提供接近 Grafana 的查询和图表配置能力，便于内部沉淀标准大盘。
- 对客户高级用户：通过模板和预置查询降低创建门槛，避免从零理解所有指标表达式。
- 对国企客户交付：界面风格专业、克制、现代，体现平台完整度和可信度。
- 对日常使用：信息密度高、层级清晰、支持浅色/深色主题，适合长期使用。

## 4. 用户角色

### 4.1 公司技术人员

主要使用者。需要创建和维护可观测性大盘，支持自定义查询、图表配置、布局调整和问题排查。

### 4.2 客户高级用户

具备一定技术背景，需要基于模板或预置查询创建符合自身业务场景的大盘。

### 4.3 普通查看用户

主要查看有权限的大盘，不负责创建和编辑。查看到的数据受自身数据组权限限制。

### 4.4 平台管理员

负责菜单权限分配和系统维护。管理员也负责维护系统内置模板和预置查询随版本发布。

## 5. 产品范围

### 5.1 MVP 范围

- 新增“我的大盘”一级菜单。
- 支持大盘列表、查看、新建、编辑、复制、删除。
- 支持模板创建和空白创建。
- 支持 APO 原生大盘展示页，不使用 Grafana iframe。
- 支持网格式布局编辑。
- 支持添加、删除、复制组件。
- 支持拖拽调整组件位置和大小。
- 支持组件右侧配置面板。
- 支持图表类型：折线图、面积图、柱状图、单值指标、表格、TopN 排名。
- 支持指标数据查询，查询语法为 PromQL / VictoriaMetrics。
- 支持预置查询和自定义查询两种查询模式。
- 支持查询预览、语法校验和错误提示。
- 支持大盘级变量，变量可在查询中引用。
- 支持变量候选值按当前用户数据组权限过滤。
- 支持大盘权限：默认所有人可见，可改为团队可见或个人可见。
- 支持数据权限：查询结果始终受当前用户数据组权限限制。
- 创建入口在“我的大盘”页内提供，不单独配置创建功能权限。
- 支持保存即生效。
- 支持未保存提醒。
- 支持浅色和深色主题，与系统主题联动。
- 支持全局时间范围和自动刷新，与系统时间选择器联动。

### 5.2 明确不做

- 不使用 Grafana iframe 作为自定义大盘展示界面。但不删除原有大盘界面。
- 不提供绑定已有 Grafana 大盘 URL 的功能。
- 不支持日志查询、链路查询、告警事件查询。
- 不支持 SQL 查询。
- 不支持跨数据源混合查询。
- 不支持草稿、发布、版本历史和回滚。
- 不支持管理员在线维护预置查询模板；预置查询随版本发布。
- 不做指挥中心式大屏编辑器。
- 不支持自由画布、图层、背景装饰和复杂动效。

## 6. 信息架构

### 6.1 菜单结构

现有系统大盘可以保持当前位置。新增一级菜单：

- 我的大盘
  - 大盘列表
  - 用户有权限查看的大盘

用户创建的大盘应可在“我的大盘”中访问。具体展示形式可以是“我的大盘”列表页，也可以在左侧菜单中展示常用大盘入口，但必须保证大盘数量较多时导航不失控。

### 6.2 大盘列表

大盘列表展示用户有权限查看的大盘。

列表字段建议：

- 大盘名称
- 描述
- 创建者
- 可见范围
- 更新时间
- 最近访问时间
- 操作：查看、编辑、复制、删除

操作权限要求：

- 只有创建者可以编辑和删除自己创建的大盘。
- 有查看权限的用户可以复制大盘，复制后自己成为新大盘创建者。
- 当前不设置独立的创建功能权限；能进入“我的大盘”的用户可以在页面内新建或复制大盘。

## 7. 大盘生命周期

### 7.1 新建大盘

用户具备“我的大盘”菜单权限后，可以在“我的大盘”页面内新建大盘。

新建方式：

- 模板创建：从系统内置模板开始，快速生成大盘结构。
- 空白创建：从空白网格开始，自行添加组件和查询。

### 7.2 编辑大盘

大盘创建者可以编辑大盘。

编辑内容包括：

- 名称
- 描述
- 可见范围
- 变量配置
- 组件增删复制
- 组件位置和大小
- 图表类型
- 查询配置
- 图表展示配置

### 7.3 保存大盘

编辑后点击保存，保存成功立即生效。

要求：

- 不做草稿和发布流程。
- 修改后页面进入未保存状态。
- 离开页面前提示用户存在未保存修改。
- 保存失败时保留当前编辑内容，并提示失败原因。

### 7.4 复制大盘

用户可以复制有查看权限的大盘。

复制后：

- 新大盘创建者为当前用户。
- 默认名称为“原名称 - 副本”。
- 默认可见范围为个人可见，用户可自行修改。
- 查询、变量、布局和组件配置复制自原大盘。

### 7.5 删除大盘

只有创建者可以删除自己创建的大盘。

删除要求：

- 删除前二次确认。
- 删除后查看入口立即失效。
- 已打开页面刷新后应提示大盘不存在。

## 8. 大盘编辑器

### 8.1 编辑器形态

MVP 采用网格式编辑器，体验接近专业运维工作台，而不是自由画布大屏编辑器。

编辑器应包含：

- 顶部工具栏：保存、取消、预览/查看、刷新、时间范围、主题入口。
- 左侧或顶部组件入口：添加组件、选择模板组件。
- 中央网格画布：展示和调整组件。
- 右侧配置面板：编辑大盘、变量、组件、查询和样式。

### 8.2 网格布局

支持能力：

- 拖拽组件位置。
- 拖拽调整组件宽高。
- 组件对齐到网格。
- 组件之间避免重叠。
- 支持复制组件。
- 支持删除组件。

布局要求：

- 默认布局适配常见桌面分辨率。
- 组件标题、图例、坐标轴、表格内容不能互相遮挡。
- 组件最小尺寸应保证核心内容可读。

## 9. 组件能力

### 9.1 图表类型

MVP 支持：

- 折线图
- 面积图
- 柱状图
- 单值指标
- 表格
- TopN 排名

### 9.2 组件通用配置

每个组件应支持：

- 标题
- 描述
- 图表类型
- 查询配置
- 单位
- 小数位
- Legend 配置
- 阈值配置
- 空状态展示
- 错误状态展示

### 9.3 查询预览

编辑查询时应支持预览。

预览要求：

- 预览结果使用当前时间范围和变量值。
- 查询失败时显示可理解的错误信息。
- 查询无数据时显示无数据状态。
- 查询成功后展示图表预览或数据表预览。

## 10. 查询能力

### 10.1 数据范围

MVP 只支持指标数据。

支持：

- PromQL 查询。
- VictoriaMetrics 兼容查询。
- 时间序列查询。
- 即时查询可作为可选能力。

不支持：

- 日志查询。
- 链路查询。
- 告警事件查询。
- SQL 查询。
- 多数据源混合查询。

### 10.2 查询模式

组件查询支持两种模式。

#### 预置查询

预置查询由 APO 平台内置，随版本发布。

要求：

- 按场景分类展示。
- 用户不能新增、编辑或删除预置查询模板。
- 用户只能填写模板暴露的参数。
- 参数可以引用大盘变量。
- 预置查询应提供名称、说明、适用图表类型和参数说明。

第一批预置查询建议：

服务指标：

- 请求量 QPS
- 错误率
- 平均延迟
- P95/P99 延迟

实例/Pod 指标：

- CPU 使用率
- 内存使用率
- 网络流量
- 重启次数

基础设施指标：

- 节点 CPU
- 节点内存
- 磁盘使用率

#### 自定义查询

自定义查询面向公司技术人员和高级客户。

要求：

- 用户可输入 PromQL / VictoriaMetrics 查询语句。
- 支持语法校验。
- 支持查询预览。
- 支持变量引用。
- 支持 Legend 配置。
- 查询错误需要展示错误位置或错误原因。

### 10.3 查询安全

- 查询执行必须经过后端。
- 后端必须结合当前用户数据组权限限制查询范围。
- 前端变量过滤不能作为唯一权限手段。
- 用户输入查询不能绕过数据组权限。
- 查询应有超时、最大返回点数和资源消耗限制。

## 11. 变量能力

### 11.1 变量定位

变量同时服务于设计侧和展示侧。

设计侧：

- 创建者定义大盘变量。
- 查询语句可以引用变量。
- 预置查询参数可以绑定变量。

展示侧：

- 查看者在大盘顶部切换变量值。
- 变量变化后刷新引用该变量的组件。
- 同一个大盘可复用于不同服务、命名空间或实例。

### 11.2 MVP 系统变量

MVP 支持系统变量：

- 数据组
- 集群
- 命名空间
- 服务
- 实例/Pod
- 时间范围

### 11.3 变量权限

- 变量候选值必须按当前登录用户的数据组权限过滤。
- 不同用户查看同一个大盘时，变量候选值可能不同。
- 当用户没有某变量的可用候选值时，应显示无可用数据或无权限提示。
- 大盘共享不会扩大用户的数据权限。

## 12. 权限模型

当前权限分为两层：菜单权限和大盘权限。数据查询继续沿用全局数据组权限，但不作为新建大盘的功能权限。

### 12.1 菜单权限

“我的大盘”是菜单权限。创建入口是“我的大盘”页面内操作，不作为独立菜单或独立功能权限。

要求：

- 具备“我的大盘”菜单权限的用户可以进入列表页。
- 具备“我的大盘”菜单权限的用户可以在列表页新建大盘。
- 有查看权限的用户可以复制可见大盘生成自己的新大盘。

### 12.2 大盘权限

大盘权限控制谁能看到和打开大盘。

可见范围：

- 所有人可见。
- 团队可见。
- 个人可见。

默认值：

- 新建大盘默认所有人可见。

编辑规则：

- 只有创建者可以修改大盘可见范围。
- 只有创建者可以编辑和删除大盘。
- 其他用户即使可见，也只能查看。

### 12.3 数据权限

数据权限控制用户能查询和看到哪些数据。

规则：

- 数据权限由用户所属数据组决定。
- 大盘可见不等于数据可见。
- 同一个大盘对不同用户展示的数据可能不同。
- 查询执行必须根据当前用户的数据组权限过滤。
- 变量候选值也必须根据当前用户的数据组权限过滤。

示例：

- 大盘 A 设置为所有人可见。
- 用户甲属于数据组甲，只能看到数据组甲内服务和指标。
- 用户乙属于数据组乙，只能看到数据组乙内服务和指标。
- 两人打开同一个大盘时，变量候选值和查询结果按各自数据权限返回。

## 13. 展示页

### 13.1 展示形态

展示页为 APO 原生工作台大盘，不使用 Grafana iframe。

展示页应支持：

- 顶部变量选择器。
- 时间范围选择。
- 自动刷新。
- 手动刷新。
- 组件全屏查看。
- 浅色/深色主题。
- 查看无权限、无数据、查询失败等状态。

### 13.2 视觉风格

视觉方向为专业运维工作台，且对于非技术领导层来说够高大上。

要求：

- 支持浅色和深色主题。
- 信息密度高，但层级清晰。
- 配色克制、现代、专业。
- 适合技术人员长期使用。
- 面向国企客户演示时体现完整度、稳定性和可信度。
- 不使用过度装饰、复杂动效或大屏式视觉堆叠。

## 14. 模板能力

### 14.1 模板定位

模板用于快速创建大盘。模板提供默认布局、默认组件、默认查询模式和默认变量配置。

模板由 APO 平台内置，随版本发布。

### 14.2 MVP 模板

第一批模板建议：

#### 服务健康模板

面向服务负责人和排障人员。

默认组件：

- 请求量 QPS
- 错误率
- P95/P99 延迟
- 服务实例状态
- CPU / 内存使用率
- 慢接口 TopN

#### 基础资源模板

面向基础设施和集群负责人。

默认组件：

- 节点 CPU 使用率
- 节点内存使用率
- 磁盘使用率
- 网络流量
- Pod 状态分布
- 资源使用 TopN

#### 空白模板

提供空白网格，仅包含默认时间范围和系统变量。

### 14.3 模板要求

- 模板必须可编辑，用户创建后可以调整组件、查询和布局。
- 模板应提供默认变量配置。
- 模板应尽量使用预置查询，降低首次配置成本。
- 模板升级不能破坏用户已创建大盘。

## 15. 异常处理

### 15.1 查询失败

查询失败时应展示：

- 错误类型。
- 错误原因。
- 建议处理方式。

常见失败：

- 查询语法错误。
- 查询超时。
- 返回数据过大。
- 用户无数据权限。
- 指标不存在。

### 15.2 无数据

无数据时应明确区分：

- 当前时间范围无数据。
- 当前变量选择无数据。
- 当前用户无权限访问相关数据。

### 15.3 保存失败

保存失败时：

- 保留当前编辑内容。
- 显示失败原因。
- 允许用户重试。

## 16. 非功能需求

- 大盘页面首次加载应保持可接受响应速度。
- 单个大盘组件数量应有合理上限，避免查询和渲染压力失控。
- 查询应设置超时、最大返回点数和并发限制。
- 查询执行必须审计用户、时间、查询语句和数据范围。
- 所有用户可见文案应支持中英文国际化。
- 图表在常见桌面分辨率下应保持可读。
- 大盘配置应便于后续导入、导出或迁移。

## 17. 成功指标

- 公司技术人员可以在 APO 内完成自定义指标大盘创建，无需跳转 Grafana。
- 用户可以通过预置查询和自定义查询完成常见指标图表配置。
- 用户可以拖拽布局并保存生效。
- 不同数据组用户查看同一大盘时，数据权限隔离正确。
- 大盘展示界面与 APO 视觉体系一致，客户演示时不再依赖 Grafana iframe。

## 18. 后续演进

后续可考虑：

- 支持日志查询。
- 支持链路查询。
- 支持告警事件组件。
- 支持管理员维护预置查询模板。
- 支持版本历史和回滚。
- 支持大盘导入导出。
- 支持大屏展示模式。
- 支持更丰富的图表类型。
- 支持组件联动和钻取。

## 19. 待确认问题

- 第一批图表组件的最终清单。
- 第一批内置预置查询模板的最终清单。
- PromQL / VictoriaMetrics 查询的具体兼容范围。
- 系统变量候选值的数据来源和级联关系。
- 大盘数量较多时，“我的大盘”在左侧菜单和列表页之间的展示策略。
- 单个大盘最大组件数、单个组件最大查询数和查询并发限制。
