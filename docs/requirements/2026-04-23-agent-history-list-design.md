# /agent 历史对话列表需求设计

## 一、文档目的

本文档用于定义 `/agent` 页面一期历史对话能力的需求范围、交互方式与实现约束。

本期目标是让用户不再依赖手工拼接 `threadId` URL，而是可以直接在 `/agent` 页面内看到并打开自己账号下的全部历史对话。

## 二、需求摘要

一期目标体验如下：

- 当前登录账号可以查看自己名下的全部 `/agent` 历史对话
- 历史对话入口直接放在 `/agent` 页面内
- 页面采用左侧固定历史入口、右侧聊天主区域的双栏布局；桌面端保留固定 `Sider` 但一期默认收起
- 用户点击某条历史对话后，仍留在当前 `/agent` 页面内查看
- 打开的历史对话会把 `threadId` 写入 URL，支持刷新和直达
- 用户打开自己历史列表中的历史对话后，可以继续在同一线程里追问

本期不涉及管理员视角，也不做历史标题补齐。

## 三、背景现状

当前 `/agent` 的历史回放能力本质上已经存在，但入口不可用：

- 前端会从 URL 读取 `threadId`
- 如果 URL 中带有 `threadId`，页面可以通过 `/ai/api/v1/conversations/messages` 加载对应历史消息
- 后端侧也已经存在会话历史相关接口，例如：
  - `GET /api/v1/conversations/messages`
  - `GET /api/v1/conversations/list`
  - `DELETE /api/v1/conversations/delete`

但当前 `/agent` 页面并没有一个可见、可操作的历史会话列表，因此用户只有在已知具体 `threadId` 的前提下，才能回看历史对话。

## 四、核心问题

用户无法在 `/agent` 页面中直接发现和访问自己的历史对话。

当前缺失的能力包括：

- 页面内可见的历史对话列表
- 基于当前账号的历史对话隔离
- 点击历史对话后进入 `/agent?threadId=...` 的直达能力

## 五、目标与范围

### 5.1 一期目标

1. 在 `/agent` 页面中展示当前登录账号自己的全部历史对话
2. 使用左侧固定列表承载历史入口，右侧保留聊天主区域
3. 点击历史对话后在当前页面内打开对应线程
4. 将当前选中的历史线程同步到 URL `threadId`
5. 打开自己历史列表中的历史线程后允许继续追问，并沿用同一个线程
6. 新对话从首条用户消息开始就形成可直达的 `threadId`，并在持久化后进入当前用户历史列表
7. 采用低成本标题策略，优先快速落地

### 5.2 非目标

以下内容明确不属于本期范围：

- 管理员查看所有用户历史对话
- 通过左侧列表、管理视角或检索视图查看其他账号的会话
- 搜索、筛选、收藏、置顶、标签等增强能力
- 在 UI 中删除、重命名历史会话
- 对历史存量数据做标题补齐
- 一期强制接入 AI 自动摘要标题

## 六、目标用户

- 使用 `/agent` 的当前登录企业版用户
- 核心列表视图仅限当前账号

本设计不包含跨账号历史管理要求，但一期继续保留基于已知 `threadId` 的 URL 直达能力，用于兼容轻量分享访问。

## 七、用户故事

### 7.1 历史查看

作为一个登录后的 `/agent` 用户，我希望在页面左侧直接看到自己过去的历史对话，这样我就不需要手工拼接 URL 才能回看之前的线程。

### 7.2 URL 直达

作为一个用户，我希望选中的历史对话能够同步写入 `threadId` 到 URL，这样刷新页面后仍能回到同一条历史线程。

### 7.3 历史续聊

作为一个用户，我希望从自己的历史列表打开历史对话后还能继续追问，而不是被迫开始一个新线程。

## 八、交互设计

### 8.1 页面布局

`/agent` 页面调整为双栏布局：

- 左侧：固定历史入口（桌面端为固定 `Sider`）
- 右侧：现有聊天主区域

左侧历史入口应作为页面内一级能力存在，而不是折叠在二级弹窗或下拉菜单中。

补充约束：

- 桌面端保留固定 `Sider` 形态，但一期默认收起，并通过 header 常驻开关重新展开
- 窄屏设备如果无法稳定承载固定双栏，允许退化为可展开历史面板
- 但无论采用哪种窄屏形态，都不能破坏“查看历史、打开历史、继续追问”的核心能力

### 8.2 历史列表展示内容

一期每条历史对话展示：

- 标题
- 时间

本期不要求展示：

- 最近消息摘要
- 创建人信息

时间字段语义要求如下：

- 列表排序与时间展示共用同一个 `timeValue` 时间基准字段
- `timeValue` 优先表示最近活跃时间
- 如果一期后端暂不具备稳定的最近活跃时间输出，可在整个版本中统一退回展示创建时间
- 同一版本中，列表排序规则与展示时间语义必须保持一致，避免用户看到的时间与排序逻辑不一致

时间展示格式要求如下：

- 1 小时内：显示为 `N 分钟前`
- 当天且超过 1 小时：显示为 `N 小时前`
- 昨天：显示为 `昨天 HH:mm`
- 7 天内：显示为 `N 天前`
- 超过 7 天：显示为 `YYYY-MM-DD HH:mm`

说明：

- “近的时间”优先使用相对时间表达，例如 `几分钟前`、`几小时前`、`几天前`
- 当进入绝对时间展示区间后，统一使用 `YYYY-MM-DD HH:mm`
- 最终展示文案由前端基于同一时间基准字段格式化生成

### 8.3 列表排序

历史列表应按 `timeValue` 倒序展示，最新的对话排在最前面，方便用户优先打开最近使用的线程。

说明：

- 如果一期后端已稳定提供最近活跃时间，则按最近活跃时间倒序
- 如果一期统一退回创建时间，则排序与展示都必须统一基于创建时间

### 8.4 点击行为

用户点击某条历史对话后：

1. 页面仍停留在 `/agent`
2. 右侧聊天区域加载对应线程历史消息
3. 浏览器 URL 更新为 `/#/agent?threadId=<选中的线程ID>`
4. 左侧当前选中项高亮

### 8.5 空状态

如果当前账号下没有任何历史对话：

- 左侧列表区域展示空状态提示
- 右侧仍可正常开始新对话

### 8.6 新对话状态

本期需要明确新对话与历史线程的切换语义，页面至少需支持以下状态：

- 未选择历史线程时进入新对话状态
- 清空当前对话后返回新对话状态
- 用户在新对话状态发送首条消息时，系统必须建立新的 `threadId`，并在发出时或不晚于发出后立即写入 URL
- 新线程持久化成功后，该线程应在不整页刷新的情况下进入当前用户左侧历史列表
- 一期不得恢复或复用当前基于 `localStorage` 的本地 session 管理模式；当前选中线程的唯一来源应为 URL 中的 `threadId`

## 九、标题策略

### 9.1 一期规则

一期历史对话标题默认取该会话中的首条用户提问。

要求如下：

- 新建会话时直接按该规则落标题
- 不对已有历史记录做批量重算
- 老数据如果已经有持久化标题，则直接使用
- 如果个别老数据缺少可用标题，则使用确定性兜底占位文案，不阻塞列表展示

### 9.2 本期明确约束

本期不要求：

- 补齐旧历史的标题
- 对存量数据重新生成摘要标题

### 9.3 后续 TODO

后续版本可扩展为自动摘要标题，但需遵循以下原则：

- 摘要标题不是本期上线前置条件
- 摘要失败时应回退到首条用户提问

该能力应作为后续独立需求处理。

## 十、列表归属与分享边界

### 10.1 左侧历史列表归属

左侧历史对话列表必须以 creator 维度展示，只显示当前登录账号自己创建的会话。

这里的“自己的历史对话”仅约束左侧列表视图，不等同于 `threadId` 的直达访问权限。

必须满足：

- 历史列表接口只能返回当前账号创建的会话
- 当前用户左侧列表中默认不展示其他 creator 的线程

### 10.2 URL 直达与轻量分享

本期保留 `threadId` URL 直达能力，并将其视为一期轻量分享方式。

这意味着：

- 用户可以通过手工输入 URL 或分享链接打开某个已知 `threadId`
- 即使该线程 creator 不是当前登录账号，页面仍允许回放历史内容
- 至于非 creator 在该线程中的继续追问，本期不把它定义为正式支持能力
- 但本次也不要求为了这条未定义行为额外增加主动拦截
- 但该线程不会因为被当前用户打开，就自动进入当前用户左侧“我的历史对话”列表

换句话说，本期需要明确区分两层能力：

- 左侧列表：按 creator 维度查看自己的历史
- URL 直达：按 `threadId` 打开任意已知线程，用于兼容分享

### 10.3 后续分享能力预留

后续版本可能引入更严格的显式分享能力，例如：

- 只有被明确分享的线程才能跨 creator 打开
- 使用独立 share token / share link，而不是直接把 `threadId` 视为访问凭证

因此本期设计应预留演进空间，但不阻塞当前基于 `threadId` 的分享式访问。

## 十一、功能需求

### 11.1 creator 元数据要求

每个 `threadId` 都必须绑定 creator / owner 元数据。

当前实现校验结果如下：

- AgentSRE 的 `conversations` 表已经存在 `user_id` 字段
- 该字段可以直接复用为 creator / owner 字段，不要求新增数据库列
- 但当前写入链路仍把 `user_id` 固定写成 `syncause`，无法满足“左侧列表按真实账号查看”的目标

因此本期实施时必须把会话写入逻辑改为：

- `Conversation.user_id` 写入真实当前登录账号
- creator 表示线程创建者，不因后续分享访问者变化而被重写

### 11.2 前端需求

1. `/agent` 页面必须新增左侧固定历史入口；桌面端保留固定 `Sider` 并允许默认收起
2. 历史列表必须请求当前账号自己的历史会话数据
3. 每条历史记录必须同时展示标题和时间
4. 点击列表项必须加载对应线程并更新 URL 中的 `threadId`
5. 直接访问 `/agent?threadId=...` 仍必须可正常回放该线程
6. 用户从自己的历史列表打开历史线程后，必须允许继续追问
7. 历史列表必须支持无数据空状态

### 11.3 后端需求

1. 历史会话列表查询必须按 creator / 当前账号维度过滤
2. 基于 `threadId` 的历史回放在本期不要求按 creator 做访问拦截，以保留分享直达能力
3. 用户通过 `threadId` 打开其他 creator 的线程时，不得把该线程自动归入当前用户左侧历史列表
4. 会话创建与 creator 自身在原线程中的续聊必须保持线程归属与 creator 元数据一致
5. 标题持久化必须支持“首条用户提问”规则

## 十二、URL 与导航规则

当前选中的历史线程使用以下 URL 形式表示：

- `/#/agent?threadId=<thread-id>`

规则如下：

- 用户点击历史会话时，必须把 `threadId` 写入 URL
- 用户刷新当前页面时，应重新打开相同线程
- 用户通过手工输入 URL 或分享链接时，只要 `threadId` 有效，本期仍可直接打开对应线程
- 用户从自己的历史列表打开历史线程后继续追问，必须沿用同一个 `threadId`
- 左侧历史列表的 creator 过滤规则，不影响 URL 直达打开能力
- 用户清空当前对话时，可以移除 `threadId`，回到新对话状态

## 十三、数据契约期望

一期历史列表接口至少需要提供以下字段：

- `threadId`
- `title`
- `timeValue`

其中：

- `timeValue` 是左侧列表排序与时间展示共用的原始时间值
- 其语义应优先对应最近活跃时间
- 如果一期暂时无法稳定提供最近活跃时间，则可以先返回创建时间，但必须在前后端实现中保持一致
- 前端基于 `timeValue` 按本需求定义的规则格式化出最终显示文案

本期不强制要求额外返回摘要、状态等列表元数据。

但在线程持久化层，必须保证存在 creator / owner 元数据。当前可直接复用 `conversations.user_id`。

## 十四、异常与边界情况

### 14.1 非本人线程直达访问

如果 URL 中存在 `threadId`，且该线程 creator 不是当前账号：

- 本期仍允许通过 URL 直达打开该线程
- 页面可以展示对应历史内容
- 非 creator 在该线程中的继续追问，本期不作为正式支持能力
- 但本次不要求为了该未定义行为额外增加主动拦截
- 但该线程默认不进入当前账号左侧“我的历史对话”列表

这是一条显式产品边界，而不是实现缺陷。

### 14.2 线程不存在或已删除

如果 URL 中的 `threadId` 已不存在：

- 页面不能卡死在加载状态
- 应以右上角短暂提示的方式展示可恢复错误
- 用户仍可继续正常使用 `/agent`

### 14.3 标题为空

如果个别历史数据没有可用标题：

- 使用统一占位标题兜底
- 不得因为标题为空导致整条列表记录不可见

### 14.4 线程切换时的诊断状态隔离

如果用户从一个线程切换到另一个线程，或从历史线程返回新对话状态：

- 不仅消息列表要切换到目标线程
- 与线程绑定的 findings / evidence / 诊断详情状态也必须同步清理、重建或重新分区
- 不允许把上一个线程的诊断详情、缓存结果或工具展示残留到当前线程中

## 十五、验收标准

满足以下条件即可视为本需求达成：

1. 登录用户打开 `/agent` 后，可以看到左侧历史对话列表
2. 列表中仅包含当前账号自己的历史对话
3. 每条历史对话至少展示标题和时间
4. 时间展示符合以下规则：
   - 1 小时内显示 `N 分钟前`
   - 当天超过 1 小时显示 `N 小时前`
   - 昨天显示 `昨天 HH:mm`
   - 7 天内显示 `N 天前`
   - 超过 7 天显示 `YYYY-MM-DD HH:mm`
5. 列表排序规则与展示时间语义一致
6. 点击任意一条历史对话后，可在右侧打开对应线程
7. 点击后 URL 正确更新为带 `threadId` 的形式
8. 刷新当前 URL 后，仍能回到同一历史线程
9. 用户从自己的历史列表打开的历史线程可以继续追问，且沿用同一线程
10. 用户手工输入或通过分享链接访问其他 creator 的 `threadId` 时，本期仍可打开并回放对应线程
11. 通过 URL 打开的外部线程不会自动出现在当前用户左侧“我的历史对话”列表中
12. 会话持久化层能够为每个 `threadId` 保留 creator 元数据
13. 用户在新对话状态发送首条消息后，URL 会写入新的 `threadId`，刷新页面仍可回到该线程
14. 用户在回答仍在生成时切换历史线程或返回新对话，不会出现消息串到错误线程的情况
15. 如果历史列表采用分页或增量加载，用户仍可逐步访问自己账号下的全部历史线程
16. 切换线程或返回新对话后，不会保留上一个线程的 findings / evidence / 诊断详情状态
17. 窄屏场景下，历史列表能力仍可访问，且不会破坏聊天主区域的基本交互
18. 桌面端历史入口可以默认收起，但 header 必须始终保留重新展开入口
19. 无效 `threadId` 时，错误必须以右上角短暂提示的方式可见，而不是依赖顶部状态条或持续占据聊天主区域

## 十六、建议落地顺序

建议按以下顺序推进：

1. 先确认 APO -> AgentSRE 调用链能否透传真实当前用户；如果不能，先补齐该透传链路
2. 再修正会话写入链路中的 creator 记录方式，确保 `Conversation.user_id` 对应真实登录账号
3. 再让左侧历史列表按 creator / 当前账号维度过滤，并确定是否采用分页或增量加载
4. 然后接入 `/agent` 左侧历史列表 UI
5. 再打通新线程首发、列表点击与 URL `threadId` 同步
6. 最后做历史回放、分享直达、运行中切线程保护，以及“自己的历史线程续聊”端到端验证

## 十七、后续待办

- 后续支持自动摘要标题
- 后续评估把 `threadId` 直达收敛为显式分享能力，而不是永久把 `threadId` 当作访问凭证
- 后续视产品需要再评估是否增加时间、搜索、删除等能力
- 后续再决定是否对老历史做标题规范化或补齐

## 十八、补充实现约束与仓库范围

### 18.1 运行中切换线程保护

如果用户当前线程仍在生成回答：

- 用户点击其他历史线程前，系统必须先停止、解绑或显式隔离当前 run
- 用户执行“新对话”或清空当前对话前，也必须先停止、解绑或显式隔离当前 run
- 不允许出现旧线程消息继续渲染到新线程视图中的情况

### 18.2 新对话首发后的 URL 与列表行为

当用户处于新对话状态并发送首条用户消息时：

- 系统必须建立新的 `threadId`
- `threadId` 必须在首条消息发出时或不晚于发出后立即写入 URL
- 这样刷新页面时，用户仍能回到同一线程
- 线程持久化成功后，该线程应进入当前用户左侧历史列表
- 不要求通过整页刷新才能看到这条新历史

### 18.3 历史列表加载策略

本需求中的“能看到所有历史对话”指能力上最终可访问全部自己的历史线程，不要求 `/agent` 首屏对历史做无界全量拉取。

因此一期允许：

- 历史列表采用分页、游标或增量加载
- 首屏先展示最近一批历史
- 用户继续加载后可逐步访问全部自己的历史线程

但必须保证：

- 跨批次使用同一排序规则
- 跨批次使用同一 `timeValue` 语义
- 当前选中线程行为保持一致

### 18.4 仓库范围说明

本次需求的默认改动范围分为三层：

- 本仓库 `apo` 商业仓：
  - 负责 `/agent` 页面左侧历史列表 UI、URL 同步、运行中切线程保护、时间格式化、空状态与错误态展示
  - 负责切线程时的 findings / evidence / 诊断详情状态隔离
  - 主要改动路径为 `frontend/src/pro/**`、`frontend/public/locales/*/pro/**`
  - 由于 `/agent` 属于商业仓独有前端路径，本次默认不涉及 OSS 仓 `feat/agent-ce`
  - 本期不得在当前项目中新增或暴露历史会话删除入口，也不得依赖现有删除接口的权限语义
- AgentSRE 仓：
  - 负责会话 creator 绑定真实当前用户
  - 负责历史列表按 creator 过滤
  - 负责输出 `threadId`、`title`、`timeValue`
  - 负责无效 `threadId` 的历史回放错误语义
- 其他仓或基础设施：
  - 默认不在主范围内
  - 只有在现有 APO -> AgentSRE 调用链无法透传真实用户身份时，才需要在拥有该透传链路的网关、代理或认证集成层补充最小改动

### 18.5 外部接口兼容提醒

本项目对外部会话列表接口的依赖，应以“当前登录用户 creator 维度历史列表”为唯一受支持语义。

因此：

- 本项目不再把 `/conversations/list` 理解为“返回全部会话列表”
- 如果 owner 仓把该接口从历史全量语义收敛为 creator 语义，本项目视其为本需求所需的契约收敛
- 本项目实现阶段仍应确认当前仓没有其他受支持页面依赖该接口的旧全量语义
