# 2026-09-10

## 构建并推送 apo-front-ee v1.13.3 的 linux/arm64 镜像

产物：`registry.cn-hangzhou.aliyuncs.com/originx/apo-front-ee:v1.13.3`
（覆盖推送前的 amd64 版本，现为 arm64 单架构；用户明确选择覆盖而非多架构 manifest）

### 关键约束与解法

- **私有仓库 `192.168.1.22:81` 在办公网外不可达**（curl 502、manifest not found）。
  `frontend/Dockerfile` 的 FROM 全部指向它，直接用会失败。改用可访问的等价基础镜像：
  - build: `node:22.19.0-bookworm`（Docker Hub，arm64 已验证）
  - runtime: `registry.cn-hangzhou.aliyuncs.com/originx/nginx:stable-alpine3.20`（arm64，本地已有）
  - 临时 Dockerfile 放在 `/tmp/apo-arm-build/Dockerfile.arm64`，用 `-f` 指定，构建上下文仍是 `frontend/`，未改动仓库 Dockerfile。
- **`frontend/` 缺少 `.dockerignore`**，`COPY . .` 会把 6 万+ 文件的 node_modules 和 build/ 拖进上下文（且 macOS 的 node_modules 含 darwin 原生二进制，可能污染 Linux 构建）。
  构建期间临时创建、结束后已删除。**建议后续正式补一个。**
- **Dockerfile 里 `VITE_PUBLIC_POSTHOG_*` / `VITE_SHOW_MYSQL_HEALTH` 是死参数**：只声明了 ARG，没有 `ENV`，RUN 阶段拿不到；且 `src/` 和 `vite.config.mjs` 里 grep 不到任何引用。构建时不用传。
- **nginx.conf 有 4 个 k8s upstream**（jaeger-collector / apo-grafana-svc / apo-backend-svc / vm-alert-victoria-metrics-alert-server），
  单独 `docker run` 会 `host not found in upstream` 启动失败 —— 不是镜像问题。
  本地冒烟测试需 `--add-host=<name>:127.0.0.1`，且 curl 要加 `--noproxy '*'`（否则被代理拦截返回假 502）。
- 首页 `<title>...</title>` 是占位符，标题由 index.html 内联 JS 动态设置（"向导式可观测平台" / "APO"），非异常。

### 环境

- OrbStack docker，daemon 原生 linux/arm64 → arm64 构建免模拟，yarn 缓存命中时全流程约 1 分钟。
- 阿里云 `registry.cn-hangzhou.aliyuncs.com` 与 Harbor 凭据都在 osxkeychain，无需重新 login。
- 构建源：分支 `feat/agent-menus`，commit `58aba803`（v1.13.3 + 6 commits）。

### 重要：originx 与 kindlingx 是两个独立命名空间，别混淆

- `originx/apo-front-ee:v1.13.3` — **本次覆盖的对象**，现为 arm64（config `cccb1916…`）。
- `kindlingx/apo-front-ee:v1.13.3` — **未触碰**，仍是 amd64（config `d69cb975…`，即今早 CI 产物）。
  `.gitlab-ci.yml` 的 `DOCKERHUB_IMAGE_REPO` 指向 kindlingx；只有 originx 是手动推的。
- 若后续要把 originx 改回多架构：amd64 镜像 `d69cb975464e` 本地仍在，可用
  `docker buildx imagetools create -t <originx tag> <amd64 ref> <arm64 ref>` 合成 manifest list。
- **最终决定（用户确认）：originx 保持纯 arm64 单架构，不恢复 amd64、不做多架构。**
  即该 tag 今后只服务 arm64 环境。
